Problem Statement

Challenges in Traditional Health Consultations

Bridging the gap between medical providers and patients

⚠️ Key Industry Challenges

  • Physical Queues & Geographic Friction: Routine consultations and follow-ups require physical travel and long wait times.
  • Scattered Health Records: Paper prescriptions and disparate clinic logs result in missing medical context during critical diagnoses.
  • Scheduling Inefficiencies: Manual booking leads to double-booking, missed slots, and physician schedule mismanagement.
  • Lack of Governance: Clinics lack unified administrative metrics on doctor utilization and patient consultation completion.

💡 Platform Objectives

  • Provide instant, conflict-free online booking with verified specialist doctors.
  • Centralize digital medical advice, dosages, and follow-up plans in a patient vault.
  • Empower healthcare professionals with complete patient medical histories prior to consultation.
  • Deliver administrative transparency with actionable platform usage and appointment statistics.

Architecture

System Architecture & Design

Modular, decoupled, and secure full-stack design

💻 Frontend Layer

  • React 18 & Vite: Ultra-responsive Single Page Application (SPA).
  • Tailwind CSS: Healthcare-optimized design system.
  • Role-Based Routing: Protected route guards for Admin, Doctor, and Patient.
  • Interactive Role Switcher: 1-click persona switching for evaluators.

⚙️ Backend API Layer

  • Node.js & Express: RESTful API server with clean MVC architecture.
  • JWT Authentication: Secure bearer token authorization.
  • RBAC Middleware: Strict route isolation per user role.
  • Well-Commented Code: Highly modular controllers and services.

🗄️ Database & Storage

  • SQLite Engine: Embedded, reliable, and zero-configuration database.
  • Relational Integrity: Foreign key cascades for users, appointments, and records.
  • Pre-Populated Seeds: Realistic demo doctors, patients, appointments, and chat histories.

Database Design

Relational Data Model

Normalized relational schema with enforced constraints

Users & Schedules

  • Users: id, name, email, passwordHash, role, specialty, phone, status.
  • Schedules: id, doctorId, dayOfWeek, startTime, endTime, slotDuration, isActive.

Appointments & Care

  • Appointments: id, patientId, doctorId, appointmentDate, timeSlot, reason, status.
  • Consultations: id, appointmentId, diagnosis, medicalAdvice, prescriptionJson, followUpDate.

Records & Chat

  • HealthRecords: id, patientId, bloodGroup, allergies, chronicConditions, emergencyContact.
  • Messages: id, appointmentId, senderId, receiverId, content, sentAt.
  • Settings: key, value, description.

Security & Quality

Security & Code Quality Highlights

Built to production-grade engineering standards

🔒 Security & Privacy Standards

  • JWT Authentication: Secure bearer token authorization with expiration.
  • Role-Based Access Control (RBAC): Server-level route middleware preventing role escalation.
  • Bcrypt Password Hashing: Salt rounds = 10.
  • Sanitized SQL Queries: Parameterized queries preventing SQL injection.

✨ Code Quality & Maintainability

  • Modular Folder Structure: Decoupled routes, controllers, middleware, and database layers.
  • Comprehensive Comments: Every function includes descriptive JSDoc headers.
  • Zero-Config Database: SQLite requires no external services or Docker, ensuring seamless evaluation.
  • Demo Switcher: Instant 1-click persona switching for quick testing.
